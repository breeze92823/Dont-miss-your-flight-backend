# Don't Miss Your Flight — BACKEND (game server)

Frontend (3D client) lives at `../Dont-miss-your-flight` (`src/net.js`, `src/remote.js`, `src/store.js`). Colyseus + Mongo. A contract change goes in both projects.

- `npm start` (tsx watch, port 2567), `npm run build` (tsc -> `build/`), `npm test` (mocha + `@colyseus/testing`, Mongo faked via `__setPlayersForTest`, Bloxity faked via `__setVerifierForTest` / `__setRewardVerifierForTest`; tests share one booted server, `test/server.ts`). Node >= 22.
- One room, `world` (`src/rooms/WorldRoom.ts`), `maxClients` = `ROOM_MAX_CLIENTS` (50 = Bloxity's default seatCap). Client calls `joinOrCreate("world", { token, username, pfp, pose, trip, avatar })`. Client-authoritative gameplay: the server only bounds saves (`src/sanitize.ts`) and presence (`src/presence.ts`). `src/db.ts` degrades to "no persistence" when `MONGODB_URI` is unset/unreachable. `/health` for Legion; `/monitor` and the playground are dev-only.

## Identity (src/bloxity.ts)
- A signed-in player sends `Legion.SDK.auth.getToken()` as `token`; the server POSTs `{BLOXITY_API_URL}/v1/auth/game-token/verify` (Bearer token, body `{ gameSlug }`) and uses ONLY `user._id` as the account id. A bad / missing token = guest (never saved). A client-sent `userId` is trusted only outside production (`trustClientIds()`: `NODE_ENV !== "production"` and no `BLOXITY_ENV`) so local dev (`dev-...` ids) and the tests keep a save.
- `identify` (same shape) re-identifies after a sign-in / sign-out; `progress` / `noProgress` carry `you` { signedIn, username, uid }. A second live session on the same account is evicted.

## Saves
- Messages: `saveProgress` (store.snapshot(): `coins`, `suitcases`/`suitcase`, `hats`/`hat`, `passes`, `visited`, `dest`, `flights` ($max, never drops), `timed` { id: ends-at ms, cut to `TIMED_MAX_MS`, ended dropped }). Answers on load: `progress` (sanitized doc) / `noProgress` / `serverError` (read failed: saving stays off). Saves are ignored until the session's load answered. `playtime` (s) is counted by the server and written on leave; `lastSeen` too.
- Daily Reward (`src/daily.ts`, `DAILY_DAYS` = 7 = client `DAILY.days`): server UTC clock, `daily` / `claimDaily` -> `dailyResult` / `dailyRefresh`; doc fields `dailyDay` / `dailyLast` / `dailyClaimed`, written by the server only.
- Rewarded ads: `adReward` { rewardToken } -> POST `/v1/ads/reward/verify` { gameSlug, rewardToken } -> `adRewardResult` { ok, coins: `AD_REWARD_COINS`, test } or { ok: false, reason } (one per `AD_REWARD_COOLDOWN_MS`; a token for another account is refused). The client grants the coins.
- Trolls: `troll` { id, text } -> broadcast `trolled` { id, from, text } to everyone else, one per `TROLL_COOLDOWN_MS`, text cut to `TROLL_TEXT_MAX` (`test/Troll.test.ts`).

## Fellow passengers (roster = `WorldState.players`, src/presence.ts)
Everyone in the room is drawn by every other client as a passenger (client `remote.js`); the airport staff are each client's own bots.
- `PlayerState`: `username`, `signedIn`, `uid` (verified Bloxity id, "" for guests; chat bubbles match on it), `pfp`; pose `x`/`y`/`z`/`yaw`/`speed`/`grounded`/`anim` ("" | sit | tpose | ko); trip `zone` (airport | cabin | city; the cabin is shared by every flight, the city is per `dest`), `dest`, `line` ("" | checkin | security | boarding: the shared line they stand in), `hold` ("desk:N" | "lane:N" | "mat:N" | "scan": the spot they use, so others aren't sent to it), `suitcase`, `hat`, `vip`, `pack`, `bag`; `emote` (Bloxity emote id, "" = none); `avatar` (Bloxity look JSON, max `AVATAR_MAX_LEN`, never parsed).
- Messages: `pose` (~10/s, bounds `POSE_BOUNDS`), `trip` (on change), `emote` { id }, `setAvatar` { avatar }. The join options may carry `pose`, `trip`, `avatar`.
- `away` (server-set): the player's game stopped, so the other clients drop them from their lines and held spots. Clients send `alive` from the game loop (~1/s; clears it) and `away` { on } on tab hide/show; a client that has beaten once and then goes quiet for `AWAY_AFTER_MS` (checked every `AWAY_CHECK_MS`) is flagged, and so is a dropped connection while it waits `RECONNECT_SECONDS` to reconnect (`test/Away.test.ts`).

## Bloxity reporting
- Every `REPORT_EVERY_MS` the room reports its signed-in players: leaderboards (`BOARDS`: flights, destinations, coins; POST `/v1/leaderboards/hosted/{BLOXITY_GAME_ID}/report`, user ids `legion_<id>`, boards declared on the first call; only changed scores; a leaving / account-switching / shut-down session's last scores are sent at once, `report(only)`; `test/Leaderboard.test.ts` runs it against a fake Bloxity API) and game stats (`STATS`; POST `/v1/games/{BLOXITY_GAME_ID}/stats`, values clamped under Bloxity's ceilings). Both need `BLOXITY_REPORT_TOKEN` + `BLOXITY_GAME_ID` (skipped otherwise). The client declares the same boards (`LEADERBOARDS` in config.js).
- Open Rooms (`src/roomReporter.ts`, `installRoomReporter()` after `listen`): every 2 s POST `{MATCHMAKER_REPORT_URL}/{BLOXITY_GAME_ID}/rooms` { podName, players, rooms[] } from `matchMaker.query({})` (private rooms skipped).
- Env (injected by Bloxity hosting, see `.env.example`): `BLOXITY_ENV`, `BLOXITY_API_URL` (fallback https://api.bloxity.io), `BLOXITY_GAME_ID`, `BLOXITY_REPORT_TOKEN`, `MATCHMAKER_REPORT_URL`, `POD_NAME`, `MONGODB_URI`, `CLIENT_ORIGIN`, `PORT`.

## CI/CD
`.github/workflows/deploy.yml` tests on PRs and pushes to `main`/`dev`; pushes also build+push a GHCR image and deploy to Bloxity Legion (`main` = prod, `dev` = dev), with { channel, image, version } only (hosting.bloxity.io/docs): no room size / seatCap is sent, Bloxity's default seatCap 50 = `ROOM_MAX_CLIENTS`. Needs secret `LEGION_DEPLOY_TOKEN`; `LEGION_GAME_ID` (var/secret) defaults to `dont-miss-your-flight`. After the first push make the GHCR package public (Packages > Package settings). On SIGTERM (deploy / scale-down, Legion waits up to 10 min) Colyseus shuts down gracefully: `WorldRoom.onBeforeShutdown` stamps everyone's save and disconnects them; the clients re-resolve through the matchmaker and land on the new pod.
